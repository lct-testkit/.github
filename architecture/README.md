# Архитектура в Archi

Кейс (`rtk_requiriments.md`, разд. 6.7) требует описание функциональной и компонентной архитектуры в Archi. `rtk-school-crm.archimate` — модель в формате Open Exchange (ArchiMate 3.x), который читает [Archi](https://www.archimatetool.com/) (Import → Open Exchange File).

## Честно про проверку

Файл собран вручную по коду и README проекта — **не экспортирован из работающей модели Archi** (инструмента с графическим интерфейсом в этой среде нет). Проверено то, что можно проверить без Archi:

* корректный XML (разбирается `xml.etree`, ошибок нет);
* 49 элементов, 69 связей, ни одного дубля идентификатора;
* каждая связь ссылается на существующий элемент (source/target резолвятся);
* каждый элемент попал в дерево `organizations` (не потерян).

Не проверено: соответствие точной XSD, которую ожидает конкретная версия Archi (использованы только элементы и связи, которые совершенно точно существуют в ArchiMate 3.x — `BusinessActor/Process/Service`, `ApplicationComponent/Service/Interface`, `DataObject`, `Node`, `TechnologyService`, `Artifact`, `Assignment/Realization/Serving/Access/Triggering/Association`). Если при импорте Archi всё же покажет ошибку — откройте файл текстом, схема читаема, поправить конкретную строку быстрее, чем строить модель заново.

## Что в модели

Три слоя, как того требует ArchiMate:

* **Бизнес-слой** — роли (КАМ, руководитель, администратор, аудитор, внешний подписант, внешняя система) и процессы, которые они выполняют (ведение сделки, идентификация организации по ИНН, подписание ПЭП, импорт каталога, формирование отчёта, удаление ПДн, контроль аудита) — реализуют одну бизнес-услугу.
* **Прикладной слой** — три компонента (веб-клиент, API-бэкенд, фоновый воркер), их сервисы (сделки, организации, подпись, импорт, отчётность, идентификация, аудит, уведомления), три интерфейса (REST API, публичные страницы подписи, вебхуки) и объекты данных, которые бэкенд читает/пишет.
* **Технологический слой** — закрытый Docker-контур: Caddy (единая точка входа), PostgreSQL, Redis, SeaweedFS, Keycloak — каждый реализует технологический сервис, на который опирается прикладной слой; три Docker-образа как артефакты.

Один mermaid-эквивалент того же контура (без слоёв ArchiMate, для быстрого просмотра без Archi) уже есть в [`../README.md`](../README.md#как-устроено) — там же переменные окружения и порты.
