## 0. Факты контракта, которые определяют интерфейс

* **Скоуп по роли решает бэкенд**: KAM видит свои сделки и те, где он участник; HEAD — дерево команды; ADMIN — всё;
  AUDITOR — ничего из моей области (`DealScope.NONE`, нет `deal:read`/`organization:read`/`contact:read`). Чужой объект — **404, не 403**.
* Права (`/api/me → scopes`): `deal:read|create|update|transition` — KAM/HEAD/ADMIN; `deal:reassign`, `deal:reassign_bulk`,
  `file:delete` — HEAD/ADMIN; `organization:*`, `contact:*`, `org_lookup:use`, `file:upload|download`, `workflow:read`, `catalog:read` — KAM+.
  Уведомления и `/api/me/*` — любая роль без отдельного права. `user:read` (список пользователей) — **только ADMIN** (см. риск №1).
* Списки: курсор (`limit ≤ 100`, `next_cursor`), сортировка фиксирована `created_at desc`, **нет общего количества**, у `/deals` нет фильтра
  «только открытые» и мультивыбора статусов — только один `status_id`.
* Мутации: `PATCH`/`transition`/`reassign`/`apply-drift` требуют `If-Match: <version>` → `409 CRM-1002` с `extra.current_version`.
  `POST /deals|organizations|contacts` принимают `Idempotency-Key` (8–255 символов). Двойной переход по одной сделке → `503 CRM-9503` (лок) → «повторить».
* Переход: бэкенд сам проверяет ребро графа (`CRM-1201`), роль (`CRM-1202`), закрытость (`CRM-1203`), комментарий (`CRM-1204`), guard-условия
  (`CRM-1201` с `extra.unmet[]`). `fields` при переходе — только `amount, currency, expected_close_date, loss_reason_id, students_planned, title,
  custom_fields.*`. `attachments` в теле **игнорируется**, а контекст DSL отдаёт `attachments: {}` — guard `attachments.contract` невыполним (риск №2).
* `available-transitions` отдаёт **плоский** список листьев условий (`field/op/expected/actual/satisfied`) — структура `any/all` теряется;
  дерево условий читаю из `GET /workflows/{id}` (граф с `statuses[].required_fields`, `transitions[].conditions/actions`, `sla_rules`).
* SLA: `sla_due_at`, `status_changed_at`, `sla_state ∈ ok|warning|breached|paused`; воркер раз в 15 мин, пороги 0.75/1.0 (per-rule `warn_threshold_pct`
  не используется). Статус типа `parked` → `paused`. В сид-воронках SLA-правил нет → в демо `sla_due_at = null` у всех сделок (вопрос к B/лиду).
* Воронки из сида: B2B `b2b_university_v1` (14 промежуточных статусов + won/lost/parked), B2C `b2c_individual_v1` (6 + терминальные).
  Возврат назад и отказ/заморозка — с обязательным комментарием; `lost` требует `loss_reason_id`; `won` — `amount` и `expected_close_date`;
  `parked` — `custom_fields.resume_at` или `custom_fields.park_reason`; `kp_preparation → kp_approval` запускает `request_signature` (блок C);
  `contract_signing → lms_transfer` — `signature_status == signed` (ИЛИ вложение — невыполнимо, см. выше).
* Организация: создание по ИНН (контрольная сумма → дубль `409 CRM-1302` c `extra.organization_id/deleted` → обогащение из локального ЕГРЮЛ);
  поля из реестра помечаются `verified_source/registry_snapshot`, ручные правки поверх — `manual_overrides[]`; дрейф — `requisites_drift{field: new}`
  + `apply-drift {fields[]}`; ИП (`individual_entrepreneur`) — телефон/e-mail маскированы, полные — `POST …/reveal` (аудит `PII_REVEALED`).
* Контакт: `email/phone` **всегда** маскированы в списке/карточке (`+7 (9**) ***-**-67`, `i***@…`); каналы (telegram/whatsapp/…) — только в ответе `reveal`.
* Файлы: `upload-intent` (расширения `png,jpeg,jpg,pdf,zip,gz,gzip,rar,doc,docx,xls,xlsx,xml,csv`, SVG запрещён, ≤ 50 МБ; ссылка PUT живёт 15 мин)
  → PUT в S3 → `commit` (magic bytes, sha256, антивирус-заглушка) → `POST /attachments {file_id, entity_type, entity_id, category}`.
  Категории: `contract, presentation, act, license, report, signature_container, other`. Скачивание — `download-url?entity_type&entity_id` (TTL 5 мин).
  Привязать можно только **свой** файл (или ADMIN); отвязать/удалить — только `file:delete` (HEAD/ADMIN).
* Уведомления: `GET /notifications?is_read&priority&entity_type&event_code`, `POST /notifications/read {ids?|priority?|entity_type?|event_code?}`
  (пустое тело = все); `subject/body` уже отрендерены (могут быть `null` для динамических кодов из воронки → показываю `payload`);
  настройки — `GET/PUT /me/notification-prefs {prefs[{event_code, channels[], is_enabled, quiet_hours_start/end}]}`. Каталога кодов для не-админа нет →
  список кодов беру из `notification/seed.py` (`features/crm/notifications/eventCodes.ts`).
* `GET /me/recent` → `{items[{type,id,title,opened_at}]}` (без `response_model` → в OpenAPI `unknown`); `touch_recent` вызывается **только** для сделок.
* JSON-типы: `amount`/`price`/`total` (Decimal) приходят **строкой**, `duration_in_prev` (timedelta) — строкой ISO 8601 (`P1DT2H`), даты — `YYYY-MM-DD`, время — ISO с TZ.

## 2. Карта экранов и потоков

Общие правила: заголовок страницы — существительное, одно главное действие (primary), остальное — иконки с `aria-label`/Tooltip.
Состояния каждой страницы: скелет при загрузке (без «прыжков»), `EmptyState` с действием, `ErrorState` с «Повторить»,
409 — баннер «Данные изменены другим пользователем» + «Обновить» (введённое сохраняется). Все фильтры — в query string.
Брейкпоинты: телефон < 768 (карточки, FAB, Drawer/Modal на весь экран, `size="l"`), планшет 768–1023 (таблица без второстепенных колонок,
фильтры в 2 колонки), десктоп ≥ 1024.

### 2.1 `/deals` — список сделок

* **Видит**: заголовок «Сделки», переключатель вида `Таблица | Доска` (SegmentedControl, `?view=table|board`), быстрые фильтры-чипы
  `Все · Мои · SLA: внимание · SLA нарушен · Закрытые` (`owner_id=me`, `sla_state=warning|breached`, `closed_from=1970-01-01`), панель фильтров:
  поиск (номер/название, дебаунс 300 мс), воронка (`workflow_id`, из `GET /workflows?state=published`), статус (`status_id` из графа выбранной воронки),
  тип (b2b/b2c), приоритет, ответственный (HEAD/ADMIN; для KAM скрыт), регион, продукт/направление, период создания (`InputDate isRange`).
  Счётчики во вкладках не показываю — бэкенд не отдаёт `total`.
* **Таблица** (TableGrid, `alignCells`, `headerSticky`): Номер · Название · Организация/Контакт · Статус (Badge цветом типа статуса) · SLA (индикатор:
  точка + «осталось 2 д» / «просрочено 5 ч» / «пауза») · Сумма · Ответственный · Приоритет · Изменён. Клик по строке → `/deals/[id]`.
  Сортировка по колонкам — только в пределах загруженных строк (сервер не сортирует) → подписываю «в загруженном». Планшет: без колонок Организация,
  Приоритет, Изменён. Телефон: `TableCards` (номер, название, статус, SLA, сумма), сортировка одним Select, фильтры — кнопка с счётчиком активных.
* **Доска** (`?view=board&workflow_id=…`): колонки — промежуточные статусы воронки по `sort_order`, справа свёрнутые `Успешно`/`Отказ`/`Заморожена`.
  Данные: страницы `GET /deals?workflow_id=…&limit=100` группируются на клиенте («Показать ещё» — общая). Карточка: номер, название, организация, сумма,
  SLA-точка, ответственный. Перетаскивание карточки в другую колонку → открывает тот же диалог перехода (если перехода в графе нет — колонка недоступна).
  Телефон: колонки — горизонтальная прокрутка со snap, одна колонка на экран, переключатель статуса сверху.
* **Главное действие**: «Новая сделка» (primary; телефон — FAB). **Второстепенные**: обновить, «Недавние» (Popover c `GET /me/recent`), экспорт — нет (не мой).
* **Массовые**: выбор строк → ActionBar «Выбрано N» → «Передать другому…» (только `deal:reassign_bulk`) → Modal: преемник (пикер), причина
  (обязательна) → тост «Передано N из M» (`reassigned_count`). На телефоне — прилипающая панель снизу (как в примере rt-ui).
* **Права**: KAM/HEAD/ADMIN. AUDITOR не должен попадать на маршрут (nav лида); если попал — `EmptyState` «Нет доступа к сделкам».

### 2.2 Создание сделки (Drawer «Новая сделка», `?new=1`)

Минимум полей, остальное — в карточке: Название (автофокус) · Тип `B2B | B2C` (SegmentedControl) · Организация (`OrgLookup`: поиск по своим
организациям + подстановка из ЕГРЮЛ с созданием организации «на лету») или Контакт (B2C, пикер + «Создать контакт») · Сумма (необязательно) ·
Приоритет (по умолчанию «Обычный»). Воронка — по умолчанию опубликованная для типа; если их несколько — Select. HEAD/ADMIN дополнительно: Ответственный.
Enter отправляет, Esc закрывает, `Idempotency-Key` фиксируется на время попытки (повтор после сетевой ошибки не создаёт дубль). Успех → `goto /deals/{id}`.
Ошибки: 422 с `errors[]` → под полями; `CRM-1001` «Нет опубликованной воронки» → баннер со ссылкой на `/workflows` (для ADMIN).

### 2.3 `/deals/[id]` — карточка сделки

**Шапка** (прилипает; на телефоне — компактная, две строки): `D-2026-000123` · Название (карандаш → inline) · Badge статуса · SLA-индикатор
(`Progress` linear + текст; цвета ok/warning/breached; `paused` — «на паузе»; `closed` — «закрыта dd.mm.yyyy») · Приоритет (Tag) · Ответственный
(аватар + имя; `owner_unavailable` → предупреждающий баннер «Ответственный недоступен — назначьте нового» с кнопкой для HEAD/ADMIN) ·
Организация/Контакт (ссылки) · Сумма · подпись (`signature_status ≠ none` → Badge «На подписи/Подписано/Отклонено…»).
**Действия**: primary — «прямой» переход (первый по `sort_order` среди доступных, обычно «Перейти к статусу …»); рядом до двух вторичных
(например «Заморозить», «Отказ»); остальные и недоступные по роли — в меню «Ещё» (DropdownMenu; недоступные — `disabled` + причина в hint).
Иконки: редактировать, сменить ответственного (HEAD/ADMIN), обновить.

**Степпер воронки** (`WizardStepsHorizontal`): промежуточные статусы по `sort_order`; пройденные — по `history.statuses`, текущий — активный,
терминальный (`won/lost/parked`) — отдельный маркер после степпера. Телефон/планшет: «Шаг 5 из 14 · Сбор требований» + `Progress`, разворачивается по тапу.

**Вкладки** (`?tab=`): `Обзор · Обсуждение (n) · Файлы · Задачи (n) · История · Подписание`.
* *Обзор*: поля сделки (сумма/валюта, студентов, плановая дата, приоритет, источник, тип), пользовательские поля по `custom-field-defs`
  (`entity_type=deal`, с учётом `workflow_id`), продукты (таблица: продукт, кол-во, цена, скидка, итого — **только чтение**, см. риск №4),
  участники (список с ролью + «Добавить»), организация/контакт (мини-карточки со ссылками).
* *Обсуждение*: треды (ответы с отступом), автор/время/«изменён», системные (`is_system`) — серым без аватара, внутренние — с замком;
  Markdown через `marked` + `DOMPurify` (без raw HTML). Форма: TextArea (Ctrl+Enter — отправить), «@» — подсказка из участников/ответственного,
  чекбокс «Внутренний», кнопка «Ответить» в треде. Редактирование/удаление — по правам автора/роли.
* *Файлы*: компонент `Attachments` (`entity_type="deal"`), группировка по категориям, drag-and-drop (`FileUpload`), прогресс, ошибки по строкам.
* *Задачи*: список открытых/выполненных с чекбоксом, срок (просроченные — красным), исполнитель, приоритет; «Новая задача».
* *История*: слева таймлайн статусов (из → в, кто, когда, `duration_in_prev` в человеческом виде, комментарий, SLA на момент), справа лента событий
  (`CREATED, OWNER_CHANGED, FIELD_CHANGED, FILE_ADDED, SIGNATURE_*, IMPORT_APPLIED, WORKFLOW_MIGRATION`).
* *Подписание*: `features/signing/DealSignatures.svelte` (агент C, `{ dealId }`); вкладка показывает точку, если `signature_status ∈ pending|partially_signed`.

**Диалог перехода** (Modal; телефон — на весь экран, кнопки закреплены внизу): заголовок «Статус → «Согласование КП»», чек-лист условий
из `available-transitions` + дерева графа: группы «все условия» / «одно из условий»; ✓ выполнено, ✗ не выполнено с «сейчас: …, нужно: …».
Для невыполненных **заполняемых** условий — поля прямо в диалоге (`fields`): сумма, дата, причина отказа (Select из `/loss-reasons`),
студентов, `custom_fields.*` (тип из `custom-field-defs`, иначе текст/дата/да-нет по оператору); для незаполняемых — подсказки со ссылками:
«Прикрепите договор во вкладке Файлы» (`attachments.*`), «Требуется подпись — вкладка Подписание» (`signature_status`), «Закройте открытые задачи (3)»
(`tasks.open_count`), «Заполните поле … в карточке» (`organization_id` и т.п. — через «Редактировать»). Комментарий — обязателен при `requires_comment`
(и всегда предлагается при откате/отказе/заморозке). Кнопка «Перейти» активна, когда дерево условий выполнимо с учётом заполненных полей.
Обработка ошибок: `CRM-1201` → подсветить `extra.unmet`; `CRM-1202` → «Переход недоступен вашей роли»; `CRM-1203` → «Сделка уже закрыта», перезагрузка;
`CRM-1204` → фокус на комментарий; `CRM-1205/1206` → подсказки; `CRM-1002` → баннер «Сделка изменена другим пользователем», перечитать сделку и переходы,
форму сохранить; `CRM-9503` → «Сделка обрабатывает другой переход» + «Повторить». Успех → тост «Статус: …», перечитать карточку/переходы/историю,
если у перехода есть `request_signature` — переключить на вкладку «Подписание».

**Редактирование** (Drawer): название, сумма/валюта, студентов, плановая дата, приоритет, источник, организация/контакт, пользовательские поля →
`PATCH` с `If-Match`; 409 → баннер + «Обновить» без потери ввода. **Смена ответственного** (Modal): пикер пользователя + причина (обязательна).

## 4. Риски и вопросы к контракту бэкенда (подробно — `docs/backend-issues.md`, раздел A)

1. **Нет справочника пользователей для не-админов** — имена и пикеры (переназначение, участники, исполнители, упоминания) невозможны у HEAD/KAM.
2. **Guard по вложениям невыполним**: контекст DSL отдаёт `attachments: {}`; `TransitionRequest.attachments` игнорируется. В демо-воронках
   `contract_signing → lms_transfer` проходит только по подписи, `payment_contract → lms_enrollment` — только по `custom_fields.payment_confirmed`.
3. Список сделок: нет `total`, сортировки, мультистатуса, фильтра «открытые/закрытые» → счётчики вкладок и серверная сортировка отсутствуют; доска
   строится группировкой на клиенте.
4. Продукты сделки нельзя изменить после создания (`DealUpdateRequest` без `products`) — только чтение в карточке.
5. `available-transitions` теряет структуру `any/all` — дерево беру из графа воронки (второй запрос, кэшируется).
6. `required_fields` статуса не проверяются сервером (только `conditions`) — использую для формы, но не как блокировку.
7. Кэш карточки по версии сделки: комментарии/задачи версию не бампают → `comments_count/open_tasks_count` до 10 мин устаревшие; считаю по вкладкам.
8. `TaskOut` без номера/названия сделки → на `/tasks` пакетная подгрузка сделок с кэшем (нет `ids=` фильтра).
9. Нет счётчика непрочитанных и каталога кодов событий для не-админа → выборка до 100 непрочитанных; коды — из сида.
10. `recent` только для сделок (описание обещает организации/контакты/отчёты).
11. Сид-воронки без SLA-правил.
12. `Decimal` и `timedelta` приходят строками — парсинг на клиенте.
13. Комментарии: `body_format` нельзя задать (всегда `plain`) — рендерю Markdown безопасно; треды/история не постраничные.
14. `custom_fields` при PATCH сливаются — ключ нельзя удалить (только `null`).
15. Нет ручек: удаление сделки, филиалы (`organization_branches`), восстановление удалённой организации, «запросить доступ», каналы контакта после
    создания, DELETE справочников.
16. `file:delete` только у HEAD/ADMIN → KAM не может убрать своё вложение и файл-сироту после отмены.
17. `suggest` не отдаёт `source_id` для попаданий из внутренней базы → ссылку «Открыть карточку» даёт только `check-duplicate`.
18. Идемпотентность только у трёх POST — комментарии/задачи/вложения защищаю блокировкой кнопки на время запроса.
19. `DealCreateRequest.owner_id` принимает любого пользователя без проверки скоупа — в форме KAM поля нет.
20. Порог предупреждения SLA 0.75 зашит в воркере, `warn_threshold_pct` правила не используется.
