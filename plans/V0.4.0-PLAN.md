## 5. Инфраструктура и релиз

### 5.1 Почта — решение по вариантам

Бэкенд (`app/modules/notification/email_transport.py`) уже умеет реальный исходящий SMTP: STARTTLS/SMTPS, таймауты на каждую сетевую операцию (15с) и общий (60с), классификация ошибок (retryable/не retryable), без утечки PII в логи. Переменные `SMTP_HOST/PORT/USER/PASSWORD/FROM/STARTTLS` уже доходят до контейнеров `api`/`worker` и в compose, и в Helm-чарте (ветка `fix/helm-env-passthrough`, ещё не влита в `main` — 11 переменных единым списком). На живом `lct.velikoss.ru` `SMTP_HOST` пуст — письма технически остаются в очереди «навсегда».

Важно: продукту нужна **только исходящая** почта (ссылки подписантам, уведомления) — приём почты не нужен никогда. Это радикально упрощает задачу: не нужен полноценный почтовый сервер, только SMTP-релей/аккаунт для отправки.

**Вариант (a). Свой relay-контейнер в стеке (Postfix/msmtp как relay, или более полный Maddy/Mailu).**
Технически просто поднять — но не решает главную проблему. Свой relay всё равно должен либо (1) слать письма напрямую в интернет по 25 порту — а у большинства облачных/VPS-провайдеров исходящий 25 порт блокируется по умолчанию именно из-за спам-репутации таких серверов, разблокировка занимает от нескольких часов до нескольких дней тикетом в поддержку и не гарантирована; либо (2) сам стучится в внешний smarthost с логином/паролем — и тогда это просто лишний хоп перед вариантом (b), без выигрыша. Дополнительно свой relay = свой ключ DKIM, свой мониторинг очереди, свой риск попасть в blacklist по IP VPS. Полноценный сервер (Mailu/Maddy) добавляет ещё приём почты, который тут не нужен вообще — чистый оверинжиниринг под дедлайн хакатона.

**Вариант (b). Внешний транзакционный провайдер по SMTP на домене `lct.velikoss.ru` / `velikoss.ru`.**
Рекомендуемый вариант. Требует независимо от провайдера:
- SPF (`TXT` на домене отправителя, `v=spf1 include:<провайдер> ~all`);
- DKIM (`TXT`/`CNAME`, ключ выдаёт провайдер при верификации домена);
- DMARC (`TXT _dmarc`, для старта достаточно `p=none` с адресом для отчётов — ужесточать после проверки);
- обратный PTR-адрес VPS не нужен для этого пути — доставку выполняет инфраструктура провайдера, а не сам сервер lct.
Конкретные кандидаты: раз домен `velikoss.ru`, вероятно, уже привязан к Яндексу — самый быстрый путь — почтовый ящик на бесплатном плане «Яндекс 360 для бизнеса» (`smtp.yandex.ru:587`, пароль приложения при включённой 2FA) с публикацией выданных SPF/DKIM записей; альтернативы — любой транзакционный сервис с бесплатным тарифом и SMTP-доступом (например, Mailgun/Brevo/SendPulse) — но там верификация домена/чувствительность к «sandbox-домену только для доверенных адресатов» может занять больше времени, чем есть до дедлайна. Дать явную рекомендацию — Яндекс, если домен уже там: минимум шагов, всё на русском, привычная поддержка.

**Вариант (c). Оставить симулированной, но честно показать «письмо в очереди» везде.**
Не альтернатива (a)/(b), а обязательный страховочный слой независимо от выбора: разделы справки «Задачи», «Интеграции», «О проекте» до сих пор пишут, что почта не подключена вообще — это уже неверно с сегодняшнего утра (после #15 она работает при заданном `SMTP_HOST`), но при пустом `SMTP_HOST` пользователю всё равно нигде явно не показывается, что письмо реально не уйдёт. Поправить тексты справки и, если есть время, добавить видимый статус «письмо поставлено в очередь / отправлено» рядом с действиями, которые шлют почту (приглашение, ссылка на подпись, уведомление).

**Рекомендация:** (b) с Яндекс 360 (или любым провайдером с уже подтверждённым доменом) + (c) как страховка в любом случае. Самостоятельный relay (a) — только если (b) не удастся настроить до дедлайна и почта нужна хотя бы «частично работающей» для демонстрации на нескольких заранее известных адресах судей.

### 5.2 Чистый redeploy `lct`

Владелец дал постоянное разрешение полностью снести и переустановить сервер `lct` для этого релиза — **но это последний шаг, не сейчас**. Порядок:
1. Слить весь готовый P0/P1 (backend → frontend → deploy, в этом порядке — CI фронтенда сверяет `docs/openapi.json` с backend `main`), закрыть Helm env passthrough, настроить почту (5.1).
